# ADR-0018: Collab relay — Hocuspocus (full cutover from y-websocket v1)

**Status:** Accepted
**Date:** 2026-06-22

## Context

SecWriter's realtime layer was a y-websocket v1 relay ([ADR-0014](0014-collab-server-yjs-relay.md), [ADR-0002](0002-pin-y-websocket-v1.md)). [#239](https://github.com/mttvnst-HA/secwriter/issues/239) (graded room roles: viewer/editor/owner) needs a clean per-connection read-only write-gate, which is near-free on Hocuspocus (`onAuthenticate` → `connectionConfig.readOnly = true`) but cannot be cleanly enforced on y-websocket v1. [#128](https://github.com/mttvnst-HA/secwriter/issues/128) migrates the relay to **Hocuspocus v4** as a full flag-day cutover (server **and** client together), unblocking #239.

y-websocket v1's client is **not wire-compatible** with a Hocuspocus v4 server (it connects but never syncs), so this is not a server-only deploy — `WebsocketProvider` → `HocuspocusProvider` move together. There is no trivial rollback on Render's two-service non-atomic deploy; see [the cutover runbook](../runbooks/2026-hocuspocus-cutover.md).

## Decision

Replace the y-websocket relay with a **bare `Hocuspocus` class** mounted on our own `http.createServer` (NOT the `Server` HTTP wrapper), keeping the single-port HTTP+WS topology. The relay is built in `buildHocuspocus()` inside `server/collab-server.cjs`; the legacy y-websocket path (`setupWSConnection`/`setPersistence`/`getYDoc`/`ywsDocs`/`extractDocName`) is deleted and the `y-websocket` dependency removed.

### Server

- **Bare class + manual pump.** `hocuspocus.handleConnection(conn, req, ctx)` only CONSTRUCTS the `ClientConnection` — it attaches no socket listeners. The upgrade handler pumps: `conn.on('message', d => clientConnection.handleMessage(...))` and `conn.on('close', (code, reason) => clientConnection.handleClose({code, reason}))`. Without the pump the relay accepts the upgrade but never syncs.
- **`onAuthenticate` = validate-AND-reject-non-canonical** (`server/hocuspocus-auth.cjs`, [ADR-0017](0017-room-authorization-model.md)). `documentName` is **client-supplied** (the provider `name`), so the keying is validate-don't-rewrite: derive the tenant from the token, reject any `documentName` whose tenant-half ≠ token tenant, run `checkPrincipal` + `sanitize`, and gate on the `.acl.json` sidecar. Runs in BOTH auth modes (under auth=none everything is `_public`). A reject throws a plain `Error('Unauthorized')` so every rejection closes with the same opaque reason (no tenant-mismatch vs can't-see-room signal), produces ZERO storage fetch, and happens BEFORE `onLoadDocument`. Revocation is **per-connect** ([#752](https://github.com/ueberdosis/hocuspocus/issues/752)): a fresh reconnect re-auths and is rejected, but an already-open session keeps editing until its socket drops.
- **Persistence = `SecWriterDatabase`** (`server/secwriter-database.cjs`), a `@hocuspocus/extension-database` subclass passing bound `{fetch, store}` to `super`. `store()` runs the FULL `room-serializer.serializeRoom` (.ydoc + .SEC + .comments + .lint — NOT a bare `encodeStateAsUpdate`), so all sidecars keep regenerating; write order (.ydoc last) stays owned by `ARTIFACT_CATALOG`. Carries over from the old `flushRoom`: the 8 MB pre-serialize refusal, `roomHealth.persistFailures` tracking, and per-key store re-entrancy (`_storeChains` — no two overlapping stores race the same `.ydoc` into S3/Azure). `fetch()` splits the composite `documentName` via `splitCompositeDocName` and returns the stored ydoc bytes or null.
- **Migration broker in `onLoadDocument`.** The v1→v2 substrate broker (`createMigrationCoordinator(...).ensureMigrated`, [ADR-0006](0006-pm-substrate-migration.md)) rehomes from the old upgrade handler into `onLoadDocument`. It CATCHES its own errors and RETURNS the document (preserving the editable-room + migration-partial-banner failure mode — an `onLoadDocument` throw would abort the load). A migrated doc is **persisted explicitly** (`database.store` on `result.skipped === false`): Hocuspocus attaches the store-trigger `document.onUpdate` only AFTER `onLoadDocument` returns, so without the explicit persist a migrated-but-unedited room would never persist its v2 form and would re-migrate + re-`backupRoom` on every connect. `backupRoom` runs before any mutation inside `ensureMigrated`, so the written `.ydoc` is always backed up first. Hook order is correct because the Database-extension `onLoadDocument` (populate from storage) runs before the config `onLoadDocument` (migrate) — config hooks are appended last in the extensions array and `hooks()` chains in array order.
- **Flush cadence.** `debounce: 500ms` (injectable via `hocuspocusDebounceMs`, default `DEBOUNCE_MS`), `maxDebounce: 10000ms` (starvation ceiling), `yDocOptions.gc: true`, `unloadImmediately: false` (warm-doc, below).
- **Shutdown drain.** The bare `Hocuspocus` class has **no awaitable `destroy()`**. SIGTERM/SIGINT runs `closeConnections()` → `flushPendingStores()` (void) → `await database.drain()`, wrapped in try/catch/finally so the process always closes listeners + exits even if drain rejects. `drain()` loops with a `setImmediate` yield at the TOP of every iteration (not one leading yield): `flushPendingStores()` reaches `store()` across event-loop turns, and a room with an in-flight store at SIGTERM re-flushes BEHIND its `writeRoom` IO (a macrotask), so a per-iteration yield closes a lost-write window. Termination relies on `closeConnections()` having run first (no new external edits).
- **`getActiveUsers`** reads `hocuspocusInstance.documents.get(docName).awareness.getStates()` (`Document extends Y.Doc`; `Map.get` never materializes a doc). The HTTP handler's `boundDocs` parameter is a `boundDocsView` read-through proxy (`.get`/`.keys`/`.size`) onto `hocuspocusInstance.documents`; `flushRoom` routes through `database.store`. The sweep's resident-room skip uses `hocuspocusInstance.documents.has(composite)`.

### Client (`src/lib/collab.js`)

`HocuspocusProvider` replaces `WebsocketProvider`:
- `name: room` — the **bare canonical** `<tenant>/<roomId>`, in-band (no `/ws/` URL prefix, no `?token=` in the URL).
- `token` via an async callback (`getTokenFn`) that freshens `currentToken`; re-invoked on every WS open (so a server-initiated close re-auths — [#566](https://github.com/ueberdosis/hocuspocus/issues/566) does not apply). No `provider.url` mutation.
- Four-state status mapping: `onStatus connecting` → `connecting`; `onStatus connected` (WS open, pre-sync) → `syncing`; `onSynced` → `connected`; `onStatus disconnected` → `disconnected`; `onAuthenticationFailed` → `incompatible` (sticky — see below). The y-websocket-only reconnect-backoff math (`wsUnsuccessfulReconnects`/`maxBackoffTime`) is dropped for a generic reconnecting state.
- `provider.destroy()` is a clean teardown (sets `shouldConnect=false` before close; no zombie reconnect — [#803](https://github.com/ueberdosis/hocuspocus/issues/803) does not apply at 4.3.0).
- Optional `WebSocketPolyfill` seam (`wsPolyfill`) — undefined in the browser, `ws` in Node tests.
- `trackedOrigins` (`['local-publish', ySyncPluginKey]`) is UNCHANGED — see Gate A1.

**Sticky `incompatible`.** Because `onAuthenticationFailed` does not stop the WebSocket lifecycle (the provider keeps reconnecting), a trailing `connecting`/`syncing` would clobber the `incompatible` banner — leaving an editable-looking UI where a revoked user's writes silently never persist. A session-scoped `statusIncompatible` latch (`src/lib/session-coordination.js`, set when any `incompatible` status is observed) makes it terminal in `effectiveStatus`, exactly like `schemaIncompatible`; it is coordinator-scoped, so a fresh session/room starts clean.

### Client seed re-gated on `onSynced` (option A)

The create-room seed-on-empty (`seedYBlocks` in `handleSync`) is KEPT and moved onto Hocuspocus's `onSynced`. A server-authoritative upload seed (route create through `POST /rooms/:id/upload`) was **rejected**: `/upload` returns 409 on a cold never-WS-bound room, seeds v1 Y.Text not the v2 substrate, and `writeAclIfAbsent` is auth-only (no concurrent-create protection under the default auth=none). The fragile `_serverMeta.newRoom` doc-attribute signal stays gone.

What makes the client seed safe is the **load-ordering contract** (Gate A2): Hocuspocus `onSynced` fires only AFTER `onLoadDocument`'s state is applied, so an empty observation at `synced` is a genuinely-new room, not a pre-sync artifact. The reframed [#17](https://github.com/mttvnst-HA/secwriter/issues/17) residual is a **reconnect/StrictMode re-seed** (not concurrent-create), closed by two defenses: (1) a module-level `seededRooms` per-room guard, and (2) `unloadImmediately: false` warm-doc, so a provider remount re-syncs the seed from memory rather than reloading an empty doc before the seed flushed.

## Gate results

- **A1 — UndoManager origin (PASSED).** A `HocuspocusProvider` applies remote (peer) updates with the **provider instance itself** as the Yjs origin (an object, `constructor.name === 'HocuspocusProvider'`) — not in `trackedOrigins`, not `null`, not a `'local-'` string. So peer edits stay off the local `Y.UndoManager` stack AND `handleAfterTx`'s `origin.startsWith('local-')` re-emit early-return is not taken (React still receives the block). No `trackedOrigins` rework needed. Pinned by `src/lib/__tests__/hocuspocus-undo-origin.test.js` (two-provider loopback).
- **A2 — seed safety (PASSED).** (1) Load-ordering: with a slow `readRoom`, an existing 5-block room shows 5 blocks inside `onSynced`, a new room shows 0. (2) Load-once: a second concurrent client to a room loads from the shared in-memory doc (`readRoom` called exactly once). (3) Warm-doc: `unloadImmediately: false` keeps a room in memory across an immediate remount, so the reconnect re-syncs from memory (no false-empty). (4) Client re-seed guard: a new room seeded once does not double its blocks across two `createCollabSession` mounts. Pinned in `server/__tests__/hocuspocus-server.test.mjs` + `src/lib/__tests__/hocuspocus-undo-origin.test.js`. The y-websocket stale-close eviction guard is **superseded** by single-authoritative-load + warm-doc + the `seededRooms` guard.
- **Shutdown drain (PASSED).** At N=50 rooms × ~200 blocks × 200ms simulated write latency the full drain (`closeConnections` + `flushPendingStores` + `database.drain()`) completes in ~272ms — well under the ~20s safety margin on Render's ~25s SIGTERM grace. N=50 is a pessimistic ceiling (free-plan demo, no production p99 yet — re-confirm post-launch). `drain()` is concurrent across rooms (`Promise.allSettled` of all store chains).
- **Rollback byte-compare (GREEN).** A `.ydoc` carrying the v2 `Y.XmlFragment` substrate round-trips through a bare `Y.applyUpdate` into a fresh gc doc and yields **byte-identical `.SEC`** (both `instanceof Y.XmlFragment` preconditions held). So a reverted (pre-#128) server reading post-migration v2 bytes produces the same `.SEC` — rollback is "revert the merge commit", no manual re-export. Pinned by `tests/cross-stack-rollback.node-test.mjs` (stack-agnostic: exercises the shared `serializeRoom`, boots no relay).

## Consequences / operational assumptions

- **Single-instance assumption (HARD precondition).** Hocuspocus holds each room's authoritative `Y.Doc` in ONE instance's memory. The load-once-from-memory + warm-doc seed safety AND the per-key store-chain re-entrancy guard are correct ONLY on a single instance (Render `plan: free`, no autoscaling). Moving to >1 instance REQUIRES `@hocuspocus/extension-redis` for cross-instance sync AND a distributed lock on the `.ydoc` write (the in-process guard does not protect cross-instance write races). Revisit before any autoscale.
- **Revocation latency** = "until the socket drops" (per-connect re-auth only, [#752](https://github.com/ueberdosis/hocuspocus/issues/752)) — not immediate.
- **SIGKILL is still data loss.** The drain covers SIGTERM only; an un-flushed debounce on a hard kill is lost — same exposure as the old `unref()`'d timer.
- **`debounce: 500ms`** (vs Hocuspocus's 2000ms default) matches the old flush cadence; the Phase 5.2 measurement (~272ms drain for 50×200-block rooms at 200ms write latency) shows serialize+write cost is not saturating at this cadence on realistic rooms. Raise it if a future production p99 shows I/O saturation.
- **Pinned deps:** `@hocuspocus/server`, `@hocuspocus/provider`, `@hocuspocus/extension-database` all at exact `4.3.0`. They declare `yjs`/`y-protocols` as peer deps → single hoisted copy → `instanceof` holds → [ADR-0001](0001-server-uses-commonjs.md) (CJS server) survives. A CI step (`unit-tests` job) fails if `npm ls yjs` shows more than one non-deduped copy. Node `>=22` (Hocuspocus engines). `ws` is now a direct runtime dependency.
